01Infrastruktur & Arsitektur

Ekosistem ini punya 3 pilar yang saling terhubung erat:

💻
Bot VPS (DigitalOcean)
File utama index.js ukurannya raksasa (4.017 baris). Menggunakan auth Supabase/filesystem untuk koneksi WA. Menangani webhook ke Next.js.
⚡
Next.js (Vercel)
Stateless dan serverless. Semua logic bisnis ada di API routes, auth pakai cookie @supabase/ssr.
🗄️
Supabase (PostgreSQL)
Database tunggal dengan Row Level Security (RLS). File migrasi mencapai 1.470 baris SQL.

04Dalaman Bot WhatsApp

Bot WA adalah jantung operasional, kode utamanya ada di bot-wa/index.js.

1
Sistem Gerbang Pesan: Cuma nanggepin chat yang ada prefix . (titik). Sisanya dibiarin buat dibalas Admin manusia. Kalau dipanggil "min/mimin", bot kirim sapaan sekali.
2
Antrean Kirim (Event-Driven): Jeda 2 detik (sambil ngetik), delay 500ms buat kontak sama, 1500ms buat beda kontak. Gagal 3x = pesan dibuang ke log.
3
Kunci Sesi Eksponensial: Kalau di-logout WA, bot nggak langsung hapus sesi. Dia tahan 10 menit, 20 menit, 40 menit, sampai 60 menit. Bukanya via panel /sesi/buka-kunci.
4
Sistem Anti-Padam: Mati >8 menit? PM2 restart otomatis. Eskalasi naik 8, 16, 32, max 60 menit kalau gagal terus (catatan dari tragedi 19 Ags bot diam 907 menit).
Dua Jenis Antrean (Queue)
Sistem pakai 2 lapis keamanan. wa_outbox di Supabase menampung pesan kalau server VPS/Bot mati. outbox.json di lokal VPS menampung pesan kalau Bot nyala tapi koneksi ke WhatsApp putus.

05Temuan Kritis & Utang Teknis

🔴 Password Admin Lemah (Kritis)

Variabel ADMIN_PASSWORD=bismillah di .env.local sangat berbahaya. Ini akses ke SELURUH data. Harus diganti segera.

🔴 Duplikasi di .env.local

Ada dua blok file .env.local yang isinya identik tapi terduplikasi. Berisiko bentrok kalau diupdate sebelah.

⚠️ Rate Limiter Rusak di Vercel

src/lib/rateLimit.js pakai Map memori lokal. Karena Vercel itu serverless, tiap request lari ke mesin beda. Anti-spam jadi gampang dijebol.

⚠️ Utang Teknis: index.js (4.017 Baris)

Satu file monolith raksasa berukuran 215KB di bot-wa/index.js. Susah di-debug, susah dirawat. Wajib dipecah (handlers, services, routes).
