Lapisan Keamanan & Row Level Security (RLS)

1. Next.js Middleware

File src/middleware.js menambahkan header keamanan (X-Content-Type-Options, X-Frame-Options, X-XSS-Protection) untuk semua request API. Juga memblokir akses admin workspace bila belum terautentikasi.

↓

2. Auth Token (HMAC)

Token admin dan seller disimpan di cookie HTTP‑only, ditandatangani HMAC dengan ADMIN_SESSION_SECRET atau SUPABASE_SERVICE_ROLE_KEY. Verifikasi dilakukan di src/lib/auth.js (fungsi openAdminUserToken, verifySellerToken).

↓

3. Supabase Service Role vs Anon Key

- Anon Key (client) hanya dapat mengakses tabel yang di‑allow via RLS (misal listings dengan status active, seller_profiles publik).
- Service Role Key (server) dipakai di src/lib/supabaseAdmin.js untuk operasi CRUD tanpa RLS, misalnya menulis log audit, meng‑insert listing, meng‑update pembayaran.

↓

4. Row Level Security (RLS) – SQL Migration

File supabase/migration_rls.sql mendefinisikan policy per tabel. Contoh:
CREATE POLICY "anon_read_active_listings" ON listings FOR SELECT TO anon USING (status IN ('active','sold'));
Setiap tabel sensitif (payments, reports, blacklist) tidak memiliki policy SELECT untuk anon, sehingga hanya admin (service_role) yang dapat mengakses.

↓

5. Rate Limiting & Abuse Prevention

- IP‑based limiter (fungsi rateLimitDistributed) pada endpoint /api/listings (max 10 per 10 menit).
- Honeypot fields (website, honeypot) pada payload iklan.
- Pemeriksaan blacklist WA di src/app/api/listings/route.js sebelum menyimpan.
