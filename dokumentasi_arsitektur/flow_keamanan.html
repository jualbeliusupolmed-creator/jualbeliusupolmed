Keamanan & RLS

Model keamanan berlapis (defense in depth) — dari edge middleware, autentikasi HMAC, isolasi service role, hingga Row Level Security di tingkat database.

5 Lapisan Keamanan

1

Edge Middleware (Next.js)

File src/middleware.js dijalankan di Edge Runtime Vercel sebelum request mencapai server.

Header Keamanan

  • • X-Content-Type-Options: nosniff
  • • X-Frame-Options: DENY
  • • X-XSS-Protection: 1; mode=block

Proteksi Rute

  • • Canonical domain redirect (301)
  • • Admin workspace guard
  • • Legacy route redirect mapping
2

Autentikasi HMAC Token

Cookie HTTP-only ditandatangani HMAC SHA-256. Verifikasi di src/lib/auth.js.

Admin Session

  • • Cookie: kk_admin_session
  • • TTL: 1 jam (rotasi izin cepat)
  • • Secret: ADMIN_SESSION_SECRET (min 32 char)
  • • Payload: {nonce, sub, exp}

Seller Session

  • • Cookie: seller_session
  • • TTL: 30 hari
  • • Secret: SESSION_SECRET (pisah dari admin)
  • • Rotasi: SESSION_SECRET_PREVIOUS untuk transisi
// src/lib/auth.js - HMAC verification (timing-safe) function samaAman(a, b) { const ha = crypto.createHash('sha256').update(String(a)).digest(); const hb = crypto.createHash('sha256').update(String(b)).digest(); return crypto.timingSafeEqual(ha, hb); } function verifySellerToken(token) { const parts = token.split('.'); const [payloadB64, signature] = parts; const validSignature = kunciVerifikasiPenjual().some((key) => { const expectedSig = crypto.createHmac('sha256', key).update(payloadB64).digest('base64url'); return samaAman(signature, expectedSig); }); // ... validasi exp, format WA }

4

Row Level Security (RLS) Policies

Didefinisikan di supabase/migration_rls.sql. Setiap tabel sensitif memiliki policy eksplisit.

Contoh Policy (Public Read)

-- listings: publik hanya baca active/sold ALTER TABLE listings ENABLE ROW LEVEL SECURITY; CREATE POLICY "anon_read_active_listings" ON listings FOR SELECT TO anon USING (status IN ('active', 'sold')); -- seller_profiles: publik baca semua ALTER TABLE seller_profiles ENABLE ROW LEVEL SECURITY; CREATE POLICY "anon_read_seller_profiles" ON seller_profiles FOR SELECT TO anon USING (true);

Tabel Sensitif (Tidak Ada Policy Anon)

payments reports blacklist price_offers category_subscriptions settings push_subscriptions otps

Akses hanya via Service Role (API Routes) atau policy authenticated khusus.

Admin Access Pattern

// API Route (src/app/api/admin/...) - Service Role const supa = getAdminClient(); // bypass RLS const { data } = await supa.from('payments').select('*').eq('status', 'pending'); // Client Component - Anon Key + RLS const supa = getSupabase(); // RLS aktif const { data } = await supa.from('listings').select('*').eq('status', 'active');

Rate Limiting, Honeypot & Abuse Prevention

Lapisan aplikasi untuk mencegah spam, brute force, dan bot.

Rate Limit

  • • rateLimitDistributed (Upstash/Redis)
  • • IP-based: 10 req/10min (POST /listings)
  • • Admin login: 5 req/60sec per IP
  • • Key: listing:ip:{ip}

Honeypot Fields

  • • Field tersembunyi: website, honeypot
  • • Bot otomatis mengisi semua field
  • • Request ditolak 400 jika terisi
  • • Zero false positive untuk user asli

Blacklist & Validation

  • • Tabel blacklist (WA terblokir)
  • • Cek WA session & WA form
  • • Validasi format WA ketat (10-13 digit)
  • • Reject ID sintetis (email_*, google_*)
// src/app/api/listings/route.js - Blacklist check let bl = null; const { data: blSession } = await supa.from('blacklist').select('id').eq('wa', sessionWa).maybeSingle(); bl = blSession; if (!bl && effectiveWa !== sessionWa) { const { data: blEffective } = await supa.from('blacklist').select('id').eq('wa', effectiveWa).maybeSingle(); bl = blEffective; } if (bl) return NextResponse.json({ error: 'Nomor ini diblokir admin.' }, { status: 403 }); // src/lib/constants.js - Synthetic ID rejection export function formatWa(num) { const lokal = s.split('@')[0]; if (adalahIdSintetis(lokal)) return ''; // Reject email_0812345_1234, google_*, etc. // ... }

Admin RBAC (Role-Based Access Control)

Sistem hak akses admin berbasis peran dan cakupan wilayah, didefinisikan di src/lib/admin-access.js.

Superadmin

Akses penuh semua modul & wilayah

  • • email: jualbeliusupolmed@gmail.com
  • • role: superadmin di admin_role_assignments
  • • ENV: SUPERADMIN_AUTH_USER_ID

Province Admin

Kelola provinsi yang ditugaskan

  • • Modul: marketplace, users, reports, finance, analytics, content, whatsapp, social, distribution, organization
  • • Cakupan: semua kampus di provinsi

University Admin

Kelola kampus tunggal

  • • Modul: marketplace, users, reports, content, social
  • • Cakupan: kampus yang ditugaskan saja
// src/lib/admin-access.js - Permission check export function hasAdminPermission(actor, module, action = 'read') { if (!actor) return false; if (actor.role === 'superadmin') return true; // Province Admin modules if (actor.roles?.some(r => r.role_code === 'province_admin')) { const provinceModules = ['overview','marketplace','users','reports','finance','analytics','content','whatsapp','social','distribution','organization','admin_requests']; if (provinceModules.includes(module)) return true; } // University Admin modules if (actor.roles?.some(r => r.role_code === 'university_admin')) { const uniModules = ['overview','marketplace','users','reports','content','social']; if (uniModules.includes(module)) return true; } // Owner fallback (explicit permissions) const permissions = actor.permissions?.[module]; if (Array.isArray(permissions)) return permissions.includes(action) || permissions.includes('manage'); if (permissions && typeof permissions === 'object') return permissions[action] === true || permissions.manage === true; return false; }

Praktik Keamanan & Checklist

✓ Sudah Diterapkan

  • ✓ HMAC tokens dengan timing-safe comparison
  • ✓ Service Role tidak pernah terekspos ke client
  • ✓ RLS aktif di semua tabel (migration_rls.sql)
  • ✓ Rate limiting di Edge & API level
  • ✓ Honeypot anti-bot di form publik
  • ✓ Blacklist WA dengan cek ganda (session + form)
  • ✓ Reject synthetic IDs (email_*, google_*)
  • ✓ Admin session TTL pendek (1 jam) + rotasi izin real-time
  • ✓ Cookie flags: HttpOnly, Secure, SameSite=Lax
  • ✓ CSP & security headers via Middleware

! Perlu Perhatian

  • ! Rotasi SESSION_SECRET & ADMIN_SESSION_SECRET berkala (90 hari)
  • ! Audit log admin_audit_events perlu retention policy
  • ! Bot WA session (VPS) butuh backup otomatis harian
  • ! Supabase RLS policy test otomatis (pgTAP / jest)
  • ! Rate limit distribusi (Upstash) butuh monitoring quota
  • ! CORS policy ketat untuk API routes publik
